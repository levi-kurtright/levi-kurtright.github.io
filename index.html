Quinn

Voice quoting agent for a dealer order desk.

Takes an order over the phone and returns an exact quote in seconds, from a deterministic pricing service, never the model's arithmetic. Quinn turns it into a formal Stripe Quote with a number, expiry, and PDF. When the caller accepts, Stripe generates the invoice and subscription itself. Quinn applies Stripe-validated promo codes, changes plans with Stripe proration, and compares usage-based print plans against real meter data.

Technical case study

Problem

Quoting is where revenue starts, and where it leaks. Prices get calculated by hand, discounts drift, approvals get skipped, and the hand-off from "yes" to an invoice is manual. The goal: let a dealer place an order in natural speech, keep every number exact, and turn the confirmed quote into billing without re-keying.

Architecture

Caller ↔ ElevenLabs voice agent with four webhook tools. calculate_quote hits a stateless pricing service. send_quote creates and finalizes a Stripe Quote with one-time and recurring lines. accept_quote accepts it by number, and Stripe generates the invoice and subscription. preview_subscription_change and change_subscription handle mid-term plan changes with Stripe proration. check_promo_code validates a spoken code against Stripe promotion codes before send_quote applies it. check_print_plan_options prices the dealer's metered usage on both print plans, and change_print_plan schedules a switch with a Stripe subscription schedule. create_invoice is a direct-invoice fallback. Billing questions transfer to Riley.

Design decisions

  • The agent never does math; a service owns every number
  • Invoicing runs only after the caller confirms the quote
  • Quinn reads back Stripe's own invoice number and never invents one
  • One-time and recurring split at the source: invoice vs. subscription
  • Idempotent by quote ID: a repeated "yes" or a retried call returns the original invoice, never a second one
  • Stripe secret key lives server-side, never in the agent or the prompt
  • Plan changes are two-step: the caller hears Stripe's prorated amount before anything changes, and the confirmed change bills exactly that amount
  • No invented discounts: only codes that exist in Stripe and pass its rules (expiry, minimum order, first order only), one per quote, with redemptions tracked by Stripe
  • Print-plan switches start at the next billing period, so this month's pages bill at the rates the dealer agreed to; the recommendation is honest, including "stay where you are"

Technical case study

Problem

Distributors field a steady stream of routine billing calls: "is my invoice paid," "what do I owe," "why this fee." An agent can resolve them in one call, but only if it answers from policy and live billing data, never guesses, and knows exactly when to stop.

Architecture

Caller ↔ ElevenLabs voice agent grounded in a retrieval knowledge base of billing policies, plus a check_invoice_status webhook tool. The tool looks up an invoice by number, or a dealer's open invoices by dealer ID, email, or name, and returns a spoken summary built from Stripe's own fields, including a plain-language breakdown of metered usage. check_print_usage reads Stripe meter summaries and the next-invoice preview. preview_credit and issue_credit create Stripe credit notes after the caller confirms. send_payment_link has Stripe email its hosted payment page, retry_card_payment has Stripe retry a declined card after the owner updates it in Stripe's customer portal, and check_print_credits reads Stripe Billing credits. Stripe webhooks open and close payment follow-ups automatically.

Design decisions

  • Read-only by default; the one write is a credit note, and only within policy
  • Credits: preview first, issue on a clear yes, up to $100 per invoice by phone (counting earlier phone credits), never more than is owed, never a card refund
  • Reads back Stripe's status and amounts verbatim and never invents them; usage projections are labeled as estimates
  • Never takes card or bank numbers: Stripe emails its payment page only to the billing email on file, never to an address read out on the call
  • A card retry reads back the amount and runs only after a clear yes
  • Every "a specialist will follow up" is logged first as a tracked ticket with a reference number
  • Escalates upset callers or issues over $5,000
  • Read-only by design: order and plan-change requests transfer to Quinn

Quality

Tested like production, not like a demo

Agents that move money need regression tests. Every feature above ships with automated ElevenLabs tests, and every real call is scored afterward.

Regression suite

18 automated tests across both agents

Simulated callers run full conversations against live Stripe data, and tool-call tests check the exact action and parameters. Any tool that writes to Stripe is mocked, so a test can never charge, credit, or change a real record.

Every call scored

Post-call analysis on real calls

Three pass/fail checks on every call: no money moves without a read-back and a clear yes, every number comes from a tool, and each request reaches the right agent. Four fields are extracted for reporting: dealer, intent, outcome, and dollars committed.

Caught before callers did

Bugs the tests found

A transfer loop that bounced callers between agents. An agent that said "connecting you now" and never transferred. A model that spoke its own reasoning out loud after a hand-off, fixed by moving both agents to Claude Haiku 5.5. An agent that skipped Stripe's read-back and bought credit in one breath, fixed with an explicit stop-and-wait rule.

Verified against Stripe

Numbers reconciled to the source

Every spoken figure was checked against Stripe: quote totals, prorations, credit balances, and usage overage matching Stripe's own invoice preview to the cent. Retries were tested for idempotency, so a repeated "yes" never bills twice.

How I build

Conversation and calculation, kept separate

Both agents share one principle: the model never invents the answer. Quinn calls a deterministic pricing service for every number and lets Stripe own the invoice and subscription. Riley retrieves answers from a governed knowledge base and live Stripe data, and hands off the moment a request exceeds its authority. It's the pattern I bring to enterprise AI: prototype fast, then ship with guardrails.
